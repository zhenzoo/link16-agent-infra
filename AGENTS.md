# Link16 Codex Guide

This repository is fleet-level infrastructure for Feishu ↔ agent sessions and
wmux orchestration. It transports messages and session events; content-specific
business logic belongs in the content repositories.

## Architecture

- `wmux/` is the low-level transport/RPC layer.
- `feishu/` is the bridge, runtime registry, hook → outbox → drainer pipeline,
  app registration flow, and messaging tools. Its dependency direction is
  `feishu/ -> wmux/`.
- `TOOLS.md` is the tool index. Architecture and operational procedures live
  under `docs/` using the `TYPE-NNN-slug` naming convention.
- `feishu/agent-profiles.json` is the only profile→runtime/home/launcher
  registry; `feishu/agent_runtime.py` implements provider drivers and readiness.
  Keep `feishu_bridge.py` and content repositories provider-neutral.
- `feishu/agent-registry.json` is the committed identity directory;
  `feishu/bridge-bots.local.json` is the machine-local runtime roster.

## Codex Personal Boundary

- CXP (`profile=cxp`, `CODEX_HOME=$HOME/.codex-personal`) is the recommended
  and machine-default production Codex profile. CX remains an independent
  optional profile.
- Do not modify `$HOME/.claude-personal`, Claude hooks, settings, skills, or
  authentication while maintaining Codex compatibility.
- Claude compatibility adapters are generated by
  `codex-personal/sync_claude_skills.py` under `$HOME/.agents/skills` and read
  Claude workflow sources at runtime.
- Native Codex skills use `$name`. The Feishu bridge may translate legacy
  `/name` only when `name` matches an installed skill; Codex native slash
  commands and every Claude command remain unchanged.

## Bridge Invariants

- Every Bridge main session and independent wmux worker carries exactly one
  `LINK16_AGENT_PROFILE`. Independent workers must inherit the parent's exact
  value through `feishu/agent_profile_cli.py`; missing/unknown/unhealthy values
  fail before pane creation. Never infer identity from `CODEX_HOME`,
  `CLAUDE_CONFIG_DIR`, alias, or cwd.
- Native Codex `spawn_agent` workers inherit the current harness and must not
  re-select a profile. New profile, bot, user entry document, or repository
  worker integration goes through `$agent-profile-governance`.
- Machine rosters persist only `profile` (or `defaults.profiles`); legacy
  `agent/account/claude_config_dir/codex_home` fields are read-only migration
  inputs and must not be added to new rows.
- Claude completion extraction may inspect Claude JSONL; Codex output must use
  Codex hook event records and must not assume Claude JSONL structure.
- Every Codex turn route is captured by `UserPromptSubmit` and pinned into both
  progress and answer records before the asynchronous drainer handles them.
- Keep links sent to Feishu outside inline/fenced code so they remain clickable.
- Preserve unrelated user changes in this production repository. Restarting or
  cutting over the live bridge is an operational action, not an automatic test.

## Verification

Run focused syntax and unit checks after bridge/runtime changes:

```powershell
python -m py_compile feishu/agent_runtime.py feishu/feishu_bridge.py feishu/hooks/codex_bridge_stop.py feishu/hooks/codex_bridge_posttool.py
python -m unittest discover -s tests -v
```

Use registration and hook installers in dry-run mode first. Never print app
secrets, MCP tokens, or values from the shared `.env`.
