# Align / Living Plan 轻重两版实战 A/B

## 结论

不应把“矛盾、改哪里、验收、证据”这些语义全部删掉；应删掉的是**每个 Step 无条件重复同一组字段**。

推荐采用混合合同：

- Stage 的先后顺序直接表达优先级；Step 默认不再重复 `priority`。
- 普通 Step 默认只写：动作、交付物、验收。
- 关键 Step 必须再写：真实矛盾或待决策点、精确改动位置；只有存在真实依赖或证据时才补对应项。
- 跨夜、跨 Session、并行、多写者、同一 SSOT 或不可逆/高风险任务，额外启用详细状态表；不把这套状态层强加给普通 Plan。
- 对 Step 数、依赖、状态、引用和 ETA 做机械一致性检查，避免轻量计划因手工计数而漂移。

这比“旧版全部保留”更容易读、改得更快；也比“只留几句动作”更可执行、可恢复。

## 实验方法

同一真实历史任务在两个独立 `cxp` wmux workspace 中只读执行，均读取 企业租户A-baseball 的 V3.1 冻结快照、当前 V3.2 working、PLAN 与 RESEARCH：

- A：旧版详细合同。要求 20～30 个 Step，每个 Step 固定完整元数据和六类正文。
- B：轻量合同。Stage 排序表达优先级；当前 Stage 展开，后续 Stage 紧凑；关键矛盾、依赖和改动位置按需出现。
- 第二轮向两边注入同一真实变化：P0 后继续 P1，新增三麦与真实声场图、连续曲面 3D、内部堆叠、装配物理、逐图即时交付与最终 PRD 写回。
- 全程未写 baseball 仓库、未开 GUI、未发外部消息。

- A：`ws-7c32ab82-f28b-405c-9677-fae86abcf1a3`
- B：`ws-48359efb-79c0-4640-9f09-93a615de4776`

## 实测结果

| 指标 | A · 详细版 | B · 轻量版 |
|---|---:|---:|
| 首轮完成耗时 | 16 分 53 秒 | 10 分 38 秒 |
| 首轮正文 | 21,903 字符 / 637 行 / 27 Step | 5,798 字符 / 167 行；当前 Stage 5 Step，后续 Stage 紧凑 |
| 首轮关键发现 | 状态双轴、章节引用与工程边界更完整 | 先发现 `TBR-AUD-01～04` 在两代文档中语义复用 |
| 第二轮回卷耗时 | 9 分 02 秒 | 5 分 37 秒 |
| 第二轮正文 | 8,968 字符 / 259 行 / 8 个直接受影响 Step | 3,780 字符 / 178 行 |
| 回卷可追溯性 | 27+7=34、1 重开+7 插入=8，前后一致 | 结构清楚，但自报“新增 14”与正文明确列出的 17 个新 Step 不一致 |
| 阅读负担自评 | mutation 15～25 分钟；合并全文 60～80 分钟 | mutation 更快可读，但需机械检查兜底 |

### 观察

1. 详细字段提高了跨 Session 恢复、依赖追踪和最终计数的一致性，但没有自动带来更早的关键发现。A 首轮比 B 多写约 3.8 倍字符，却没有先发现 TBR 语义复用。
2. 轻量版更早交付可审结构，也更容易在新证据到来时插入、重排和重开；但 B 的 Step 计数不一致证明“轻量”不能等于“无机械校验”。
3. 两版 ETA 都偏保守：A 首轮最后预计 01:15，实际 00:46:58 完成；B 最后预计 00:47，实际 00:38:13 完成。ETA 规则方向正确，但仍需持续记录“预计/实际/误差/原因”，而不是只展示时间。
4. baseball 当前的 PLAN-230 本身已经是有用的混合样例：上层可读计划负责方向和中间交付，执行图负责长任务状态与跨 Session 恢复。这类详细层应该按任务风险启用，不应成为所有 Plan 的默认正文。

## 对“所有 Agent / Session”的核对

桥重启后，统一卡片渲染已作用于当前运行的 8 个 Link16 bot 进程；经桥发送的新进度都会使用新卡片外壳。

但“当前 Plan、四层 ETA、绝对时间、下一交付”不是桥自动生成的数据，而是用户级规则和技能约束。因此现在不能宣称这台电脑的所有 Agent、所有既有 Session 都必然具备：

- 新开的受管 profile（`cc`、`ccp`、`ccp2`、`cck`、`cx`、`cxp`）会读到该规则；简单任务不强制展示完整计划。
- 已经运行中的旧 Session 不会因桥重启而重新加载系统指令。
- `ccw`、`ccw2`、`ccw3` 当前不在用户入口文档治理范围内，不能保证继承。

所以准确结论是：**卡片样式已经全桥统一；计划与 ETA 内容目前覆盖受管 profile 的新长任务 Session，但尚未机械覆盖全机所有 Session。**

## 正式规则落地

实验结论已在 2026-09-01 写入 `align` / `living-plan`：

1. 关键 Step 的“真实矛盾/待决策点 + 精确改动位置”已从可选提示提升为条件式必填。
2. 详细状态层只在跨 Session、并行/多写者、共享 SSOT、高风险或需要机械恢复时启用，并增加 Step/依赖/ETA 一致性检查；没有恢复每个 Step 固定六字段。

本 RESEARCH 作为 A/B 证据保留，不再承担后续执行状态；正式行为以两项 Skill 与 `PLAN-1000` 为准。
