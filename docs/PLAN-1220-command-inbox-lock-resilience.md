目标：让 `/close`、`/account` 在长期运行、网络切换、系统休眠恢复和本地并发读写下保持可恢复、可解释，单个数据库锁等待不得带崩 bot 桥；保留现有每 bot 持久收件、跨重启去重和真实接收回执，不重做无关架构。

用户输入：
1. 查清 tb26-baseball-zhen 本次 `/close`、`/account cxp2` 约两分钟无响应的直接原因和完整恢复链。
2. 彻查 `sqlite3.OperationalError: database is locked` 的产生条件；若历史证据不足，增加有效日志并主动复现，不猜测持锁进程。
3. 从架构和用户体验上修复：关机、重启、网络切换或长期闲置后，控制命令都应得到响应，不能因锁等待崩溃。
4. 流程应简洁、鲁棒，保留持久会话与命令语义；不以“重启后好了”代替根因治理。
5. 若同一文件双方有不同功能修改，保留并整合双方有效内容，不单选一边。
