3

病根 — 两层，比误投更严重

任意 agent 能冒用任意 bot 当发送者

4 个发送工具（send_feishu_msg / media / file / voice）里，--bot 参数 = “用谁的凭据发”，但——

  • 从不核对 --bot 是不是调用方本人：4 个脚本全程一次都没读过身份锚 FEISHU_BRIDGE_SESSION（桥开机钉进环境的“我是谁”）。
  • 凭据全共享：所有 bot 的密码都在同一个 .env，任意 agent 的进程都取得到。
  • 两者一叠 = 谁都能冒充谁发消息。这次三个 bot 同主人没外泄；主人不同就是真泄露。
证据 · send_feishu_media.py:106 target = a.to or sess.get("chat_id") ｜ 4 面均 0 次引用 FEISHU_BRIDGE_SESSION ｜ 凭据经 _bot_creds(--bot) 从共享 .env 取

a2a 信封的“发信人”是自己盖的 → 可伪造

agent 互相喊话时，消息尾会盖一个信封 [飞书_from_X_to_Y] 标明谁发的。问题是——

  • 这个 from_X 是发信方用自己传的 --bot 自己盖上去的。
  • 接收方反查不出真发信人（飞书 open_id 按 app 隔离，收到消息只知道“某 bot”、验不了是不是本人）。
  • 所以冒用者能把信封盖成受害者的名字当 from → 不只是发错地方，还能冒名顶替发信身份，接收方毫无察觉。
证据 · send_feishu_msg.py:312 send_text = f"{text} [飞书_from_{a.bot}_to_{a.to_agent}]" — from 直接取 a.bot（谁传的就盖谁）
4

根治方案 — 把“以谁身份发”和“发给谁”彻底分开

病根 = --bot 一个参数同时管了“身份”和“默认发到谁”。方案 = 加一道发送者身份闸，只堵冒用、不碰路由。

# me=tb25-phd-taoci 的会话里跑：
python send_feishu_media.py --bot tb25-phd-taoci-3
🛑
当场拒绝：“身份越界：你是 tb25-phd-taoci，不能用 tb25-phd-taoci-3 的身份发。发给别的 agent 请用 --to-agent（只改路由目标、不改发送者）。” — 事故被闸挡死。
python send_feishu_msg.py --bot tb25-phd-taoci --to-agent tb25-link16 # 以自己身份，发给别人
🤝
照常送达：合法 a2a 永远是“以我自己身份、发给对方”。--bot=自己 过闸；--to-agent 只改目标不改发送者，路由一点不动。对方凭据只用来查“共享群/open_id”，不用于发送。零回归。
# 纯终端 / cron 守护进程本身（没有身份锚）：
$ unset FEISHU_BRIDGE_SESSION ; python send_feishu_msg.py --bot anybot …
💻
放行：没有身份锚 = 可信操作者场景（主人手动 / 基建脚本）。terminal、cron 零回归。（注：cron 到点是把任务注入 bot 的现有会话，那会话身份锚是设着的 → 照样被闸管住，不是绕过后门。）

PHASE 1 · 止血（现在做）
身份闸放共享模块 bridge_env.py，4 个发送面各 import 一行即生效。堵住冒用 + 伪造，a2a/p2a/terminal/cron 全零回归。
PHASE 2 · 跨主人根治（以后）
凭据隔离：a2a 路由改用名册存的 open_id + 只用自己凭据查群 → 以后没有任何 agent 持有别人的密码。更大改动，先 Phase 1。
