# ARCH-140 · Agent↔Agent 通讯协议（a2a comm）—— 新模型「就是普通消息」

> **类型**：ARCH（讲它怎么运转）· band 1xx = feishu 桥
> **职责**：定义**智能体之间**怎么经飞书桥对话。
> **与 [`ARCH-110`](ARCH-110-feishu-bridge.md) 的分工**：ARCH-110 = 桥本体（@bot→注入 / hook→outbox→drainer 回传 / 多 bot）；**本档 = 架在桥之上的「agent 之间怎么对话」那一层**。
>
> **🔄 2026-07-02 大简化（主人定）**：**删掉整套「守望 / reply-wait / --wait / 轮询 / 超时 / 防回环哨兵」。a2a 就当普通消息收发。** 下文即新模型；旧的「reply-wait 守望 + 哨兵丢弃」已废（见 §2 演进）。

---

## §1 · 一句话模型

**agent↔agent 的对话都在一个共享【群】里，就当【普通消息】收发：**
- **发**：`send_feishu_msg --to-agent B` → 发到共享群、@B、盖 `[飞书_from_A_to_B]` 戳。**发完即返回**（不守望）。
- **收（对方派活给我）**：B 的桥收到「@B 的群消息」→ **注入 B 的会话**（当普通消息）→ B 处理、回复（回复经 drainer 发回群 @A）。
- **收（对方的回信回到发起方）**：A 的桥收到「@A 的群消息」（= B 的回信）→ **注入 A 的会话** → A 处理，自己判断要不要接着聊。
- **没有守望、没有 --wait、没有轮询、没有哨兵、没有机械防回环。** 发就完了，回信自然会来（桥投进你会话）。

> 对照：**主人↔bot = 私聊 DM（route=p2a）**；**agent↔agent = 群（route=a2a）**。群 = `shared_group(A,B)` 现解析（`oc_…` 不硬编码）。

## §2 · 为什么这么简单（演进 · 别再走回头路）

- **旧模型**：桥收到对端回信（尾缀隐形哨兵 `PEER_LOOP_MARK`）→ **扔掉**（防 A@B→B@A→…死循环）；发起方靠 `--wait` **主动守望**（轮询群、等结构化裁决 done/blocked/failed）才收得到。
- **旧模型的洞（2026-07-02 实证）**：**不守望就收不到** —— 发起方一旦 fire-and-forget（没传 --wait，或判断"不急"没守望），对端回信落群、桥把它扔了、没人接（实测：tb24-link16 回信 @ tb25-link16，tb25-link16 没守望 → 收不到）。
- **新模型**：桥**不再扔** —— 把「@我的群消息（含回信）」**当普通消息投进我会话**。⇒ 收到的「保证」从**「发起方记得守望」**（能忘、能跳过）搬到**「桥自动投递」**（永远在线·跳不过）。这才是真·必达。
- **防回环**：**不再机械防**（主人 2026-07-02 定：真跑飞极少·之前架构不稳才偶发·现在主要矛盾是收不到）。靠 **agent 自识别**「有需求就彼此聊、没需求就断」。**真撞上 runaway 再加保险丝**（如每对 agent >N 条/分钟就停+告警）——现在不预建。

## §3 · 结构化信号（判定只认这些）

| 信号 | 含义 |
|---|---|
| `[飞书_from_<发>_to_<收>]` 戳 | 发信方**自盖·带名字**（`send_feishu_msg` 盖）。飞书 SDK 事件给的 `open_id` 按 app 隔离、认不出名 → **这个戳才是「谁发的」的 SSOT**。桥注入信封的 `from=` 解它（`feishu_bridge.a2a_from_name`）。 |
| `msg_type == "text"` | 实质内容。**a2a 必走纯文字**——飞书把收到的卡片渲成占位 `[interactive]`，对端 bot 读不到正文。 |

## §4 · 工具原语（两个·全在 `feishu/`）

| 原语 | 谁用 | 职责 | 工具 |
|---|---|---|---|
| **send** | 发起方 | 发到共享群、@对方、盖 from 戳。发完即返回（回信桥自动投回我会话） | `send_feishu_msg.py --to-agent B --text "…"` |
| **read**（兜底手动读群） | 任何人 | 一步读【群】recent、抽 a2a 回合 | `bridge_feishu_probe.py --bot A --group --recent N` |

> 被动收（对方 @ 我 → 桥注入我会话 → 我回）= 桥自动做，不需要任何工具/守望。

## §5 · 不变量 / 红线

1. **读/发都走共享群**（`shared_group` 现解析·**禁**硬编码 `oc_`/`ou_`·禁绕 DM/对端 outbox）。
2. **a2a 必走纯文字**（卡片对端读不到）。
3. **桥把「@我的群消息」当普通消息注入**——不扔、不特殊守望、不加哨兵。这是「必达」的地基（桥永远在线）。
4. **不机械防回环**——靠 agent 自识别终止（有需求才继续对话）。
