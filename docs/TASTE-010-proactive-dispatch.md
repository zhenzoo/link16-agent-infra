# 跨仓主动工作台的分派与审阅

## 一个主号对接本人

本人只对接指定主号（零号位）。零号位管理工作台，负责收件、转达、跟进、验收和汇报；各项目执行者负责制作成品。接入新仓时登记来源项目、资料入口、可用执行者及其机器、可写范围和业务验收范例。各仓的岗位 TASTE 维护“哪些事归我、什么成果算做好”。同一人的已授权事项汇入原工作台；原件、凭据和私聊记录按原访问范围保管。

## 何时独立开工

先写明谁在什么时候等哪件成果，再看任务间有没有依赖。临近评审或阻塞他人开工列 P0，需本周交付列 P1，可顺延的小事列 P2。明天同一场评审要看两份可独立编写的文稿，两名作者可以同时开工；多笔短报销由一人逐笔预填。计算、建模和渲染派到具备相应软件与性能的机器。共同编辑一个文件时指定一名集成人。已经有人接手的任务沿原单跟进；空闲、掉线和完成要用现场状态或成品区分。

## 派单保留原话

本人明确给出的要求、示例和质量纠正按原顺序逐字交给最终执行者，保留段落、数字、否定项与附件指引。主号另起一段补上缺少的原件、改前基线、谁能写什么、验收方法和回传对象。换会话、上下文压缩或跨机中转后，按原消息标识找回正文再交接。动手前留存本项 Git 基线；验收提交只纳入本项。执行中已有新纠正，补到同一单，只续做未交的部分。

## 看成果与判断闭环

人员实名以同一组织的通讯录或本机已核实的名册为准。语音转写中的人名只作检索线索。遇到同音或重名，结合账号、部门或原会话核对；身份仍不明时保留待核。工作台和归档用实名；发消息用本人指定或在本人私聊中用过的称呼。已发原文按原样留存。

沿用同一个工作台。左侧按机器和执行者列出当前工作，空闲时保留最近有证据的分工；右侧按本业务实际交付展示。跨仓条目写来源项目、负责人和优先级。消息给收件人、原话或背景、完整草稿；文件先看最能判断质量的同版预览，再点开原件。会议、任务和项目办理节点可共用「日程与待办」；有原生审批才显示审批事项。桌面保留侧栏，手机允许单列快速跳转。

本人明确关闭，或原回复已经回答该事项时，在工作台最底部「已闭环」记录结论发生时间、实名、事项、具体结果，最新在前。能量化的结果带数值和单位。意向只记意向，尚未回答的问题继续待答。同一回执重复读取只记一次；后续新结论按实际时间另记。外部事项是否办结以原单为准。

项目交付以实物验收：打开最终文件核内容和格式，外发沟通核收件人、正文、配图和送达回执，办理事项核规范文件及原单结果。验完在该项目的时间线上归档；每个时间点只列背景、问题、答复人、结论，结论附成品或回执入口。日常群聊留在原会话。已接单、已起草或仅收到素材的业务继续跟到最终交付。

## 谁在何时汇报

执行者做好就沿原派单向主号回结果，交成品入口、实际验证和剩余限制；确实卡住就回报卡点、已保存的成果和恢复条件。主号负责追没有回音的原单、亲自验收、更新对应条目，并把同批成果合为一张本人私聊交互卡片。卡片按结果编号，**每点之间空一行**。每点写做成了什么、从哪看、哪项还要本人决定。普通过程回执留在对应任务里。

每天 09:00（上海时间）的巡检用于查漏和更新工作台；当天验收通过的成品当时汇报。执行者回主号、主号向本人交付是两次投递。区分“执行者已回”“成品已验”和“本人私聊已送达”；最后一项以正确私聊中能回读的卡片为据。具体命令与失败恢复见[主动工作流程](SOP-150-proactive-agent-loop.md)。
