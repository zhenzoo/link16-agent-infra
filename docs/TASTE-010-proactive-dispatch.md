# 跨仓主动工作台的分派与审阅

## 一个主号对接本人

本人指定的主号负责收件、排序、派单、追单、收结论、更新工作台和按授权发送消息。每项业务由原单指名的执行者查看原件、实施和验收。独立复核者只读原件，产品作者继续持有整件的写入及消息职责，主号始终只收结论和同版预览。接入新仓时登记来源项目、资料入口、执行者、可写范围和业务验收范例。各仓岗位 TASTE 维护职责及成品标准。原件、凭据和私聊记录按原访问范围保管。

## 何时独立开工

先写明谁在什么时候等哪件成果，再看任务间有没有依赖。临近评审或阻塞他人开工列 P0，需本周交付列 P1，可顺延的小事列 P2。明天同一场评审要看两份可独立编写的文稿，两名作者可以同时开工；多笔短报销由一人逐笔预填。计算、建模和渲染派到具备相应软件与性能的机器。同一物品或事项从模型、文稿、录屏/GIF、回填、自验到获准的消息统一交一名责任人，不同物品可并行。产品发布者只上架经该作者验收的同版成品。转手前收原作者停笔与封存交接回执，关联在途单并撤销旧作者的写入/外发职责。已经有人接手的任务沿原单跟进；空闲、掉线和完成要用现场状态或成品区分。

## 派单保留原话

本人明确给出的要求、示例和质量纠正按原顺序逐字交给最终执行者，保留段落、数字、否定项与附件指引。主号另起一段补上缺少的原件、改前基线、谁能写什么、验收方法和回传对象。换会话、上下文压缩或跨机中转后，按原消息标识找回正文再交接。动手前留存本项 Git 基线；验收提交只纳入本项。执行中已有新纠正，补到同一单，只续做未交的部分。

## 看成果与判断闭环

人员实名以同一组织的通讯录或本机已核实的名册为准。语音转写中的人名只作检索线索。遇到同音或重名，结合账号、部门或原会话核对；身份仍不明时保留待核。工作台和归档用实名；发消息用本人指定或在本人私聊中用过的称呼。已发原文按原样留存。

沿用原工作台。上方按业务各占一行，中间列审批，底部是项目日轴。更新时间在工作台标题上方，侧栏仅有同样式的「业务审批」「项目时间线」。四列依次为浅色大序号与登记短名、业务或收件人、实际结果与原稿入口、实际设计附件。无结果留空。消息先列实名，另起一行逐字保留实发正文。提案沿用原表并高亮拟改行；设计图或动图在结果中可点、附件中可看。普通文档给官方正文、目录或可复制本机路径。内部派单、执行记录留在原单。

审批沿用业务四列：序号与当前负责人、事项、可打开的原单或本人已保存草稿、必要附件。本人草稿须退出后重新打开，核对申请人和所填字段。实测仅能从草稿箱定位时，链接写「原表 → 草稿箱 → 更新时间 → 编辑」。产品拍板链接原比较稿，已发起的单据链接原实例。

项目日轴每屏约七天，可横向跨周、跨月。本人确认、原回复解决问题或执行者按原单验收交付后，按真实日期、项目轨、来源和事项去重登记。同日节点向下排列，名称完整可读；点击查看来源与原件。轨道使用窄色条，同机型同色，机型间留间距。节点省略类别、重复机型；初版标 V1.0，其余版本沿用原件。仅知月或区间时覆盖实际范围。

业务结果按类型登记。结果短语限 4–18 字，以已发送、已核对、已复核等登记动词起首；数值拆成指标、数值、单位。可单独登记收件人与实发原文、原稿标题与路径、来源链接、提案表的字段与单元格。已选设计附件保留原件指纹。生成器对逐行结果执行校验，拒绝「待测」「待定」、越界长句和无单位值。反例与原文例外见 `tests/test_proactive_business.py`。

## 谁在何时汇报

执行者沿原单交结果、验收结论、同版预览和剩余限制；受阻就交直接缺项、保存位置及恢复条件。主号将回执关联原单，缺证据时追原执行者或另派复核，随后更新条目。给本人只发一张按结果编号的私聊交互卡，每点之间空一行，直接给结论、能量化的指标、预览和待拍板项。过程留在原单。

每天 09:00（上海时间）的巡检用于查漏和更新工作台；当天验收通过的成品当时汇报。执行者回主号、主号向本人交付是两次投递。区分“执行者已回”“成品已验”和“本人私聊已送达”；最后一项以正确私聊中能回读的卡片为据。具体命令与失败恢复见[主动工作流程](SOP-150-proactive-agent-loop.md)。
